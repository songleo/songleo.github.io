这是一个系列文章，主要分享我最近使用 chatgpt 过程中的一些小技巧，每次分享 3 点，希望你能有所收获。

## 1 先找 ci 的失败证据

github actions 失败时，我会先让 codex 读取失败步骤和关键日志，确认实际命令、错误位置和退出码，再判断原因。可以使用已连接的 github 插件；无法读取日志时，提供脱敏内容，不让它猜测。

比如可以说：“只读检查这个失败运行，列出关键错误和相关文件，区分独立失败、连锁结果和未执行步骤。证据不足的写 UNKNOWN，暂时不要修改文件。”

## 2 按实际命令本地复现

找到失败位置后，按 ci 中的工具版本、目录和命令复现。例如格式检查失败，就先运行 `pnpm run format:check`，确认具体文件，不顺手升级依赖或跳过检查。

比如可以说：“使用与 ci 一致的命令复现失败，在 wsl 或 linux 容器中运行检查。无法复现时说明环境差异，不要直接修改测试。”

## 3 用修改和验证证据验收

确认原因后，再让 codex 做最小修复，并重跑失败检查和受影响的测试。我会同时看 diff、验证结果和未验证项，而不只看一句“已修复”。

比如可以说：“只修复已确认的问题，给出根因、修改差异和实际验证结果。不提交、不推送，等我 review。”

本地检查通过不等于远端 ci 已恢复，远端结果需要对应运行的证据。插件用法见[官方文档](https://learn.chatgpt.com/docs/plugins)。
